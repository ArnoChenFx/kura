# 任务：设置里的「自动检查更新」开关 + 左栏更新按钮右上角的新版本小蓝点

仓库根就是当前目录（一个新建的 worktree）。开工前先读：

- `AGENTS.md`（工程约定。重点：「UI 线程契约」「验证要求」「测试隔离」，以及第 4 节里「别在要参与网格点击的元素上调 Clicked/RightClicked」「部件绑定的局部变量在构建结束才被写入」两条坑）。
- `docs/note/updates.md`（kura 自更新的现状：更新器、窗口、偏好都交给 MyGo，kura 只做装配）。
- `internal/ui/app.go` 的 `SetCheckUpdates` / `CheckAppUpdateAsync`（现有「检查更新」按钮的接线范式）与 `internal/selfupdate/selfupdate.go`（只做装配的薄转发层）。

## 用户要的两件事

1. 设置弹窗里加一个「自动检查更新」开关，**默认勾上**。
2. 后台自动检查发现新版本时，左栏左下角「检查更新」按钮的**右上角显示一个蓝色小圆点**。

用户原话：「设置里添加自动检查更新选项，默认勾上。后台自动查到更新后，再左下角的更新按钮右上角显示蓝色的圆点提示有新的更新」。

## 我已核实的事实（别再重新调研，直接用）

- MyGo 更新器插件（`plugins/updater`，kura 用 `native.Plugin`）**自带**后台自动检查：每次启动约 10 秒后做当日首次检查，之后每 24 小时一次；偏好存在用户数据目录的 `updater.json`（`AutomaticChecks`，默认开），用 `updater.AutomaticChecks()` / `SetAutomaticChecks(on)` 读写，`updater.LastCheck()` 给上次成功检查时间，`updater.OnChange(fn)` 在这些值变化时于**主线程**调用 fn（一次检查成功也会触发，因为 `LastCheck` 变了）。
- 插件**没有**「检查到新版本」的回调，也没有「后台发现新版但只提示、不弹窗」的模式：后台检查（`session.User()==false`）发现新版本且没勾自动安装时，会 `s.show()` → `frontend.Show(win, false)` → `ShowInactive()`，即**弹出一个不抢焦点的更新窗口**。这是**现有行为，保持不动**（本任务只做加法，不改它）。
- 因此在没有窗口的路径上，只有 kura 自己再查一次才知道「是不是真有新版本」：`mygo.Updater.Check(ctx) (*mygo.Update, error)`（`update != nil` = 有新版本；开发构建返回 `mygo.ErrUpdatesDisabled`，打包构建才真的联网查 `releases/latest/download/update-<平台>.json`）。插件内部用的就是这个调用。
- `updater` 包的**任何**函数在插件未挂载时会 panic（`used()`）。所以：**测试里绝不直接调 `updater.*` 或 `mygo.Updater.Check`**；一律经 App 上注入的钩子（现有 `SetCheckUpdates` 就是这个范式）。
- 现有相关代码位置：`internal/ui/app.go` 的 `checkUpdates func()` 字段（约 68-73 行）、`checkingUpdate bool`（约 107 行）、`SetCheckUpdates`（约 254 行）、`CheckAppUpdateAsync`（约 696 行）；`internal/ui/view.go` 的 `viewRootsFooter`（约 305 行，两个 `railButton` 调用）与 `railButton`（约 329 行，无底色图标按钮，悬停才出浅底）；`internal/ui/settings.go` 的 `settingsState`（约 18 行）、`OpenSettings`、`viewSettingsModal`（约 246 行）；`main.go` 的 `app.SetCheckUpdates(selfupdate.CheckForUpdates)`（约 67 行）。
- 设置弹窗里「界面语言」下拉是**即时生效**的偏好（选中即静默写盘，不经过「保存」），代码里有注释说明理由；新开关按同一套做法。
- 偏好即时生效的写法范式看 `SetThemeAsync` / `SetViewAsync` / `SetLangAsync`（立刻改内存里的值、后台写盘、写失败只在状态行报告不回滚、连续切换只有最新一次写盘）。
- 颜色**只能**从 `internal/ui/theme.go` 来（`tone`/`palette`），视图代码里不写十六进制。

## 设计边界（已拍板，照做；有异议先问我，不要自己改方向）

- **开关的持久化落在插件的 `updater.json`**（不是 `config.json`）：读 `updater.AutomaticChecks()`、写 `updater.SetAutomaticChecks(on)`。这样只有一个真值来源，默认值天然是「勾上」（插件默认开），也跟插件自己的调度一致（关掉后插件不再后台检查）。
- **不关插件的后台检查**（不设 `DisableAutomaticChecks`），现有行为一律不动。
- **小蓝点的信号来自 kura 自己的一次查询**：插件每次完成一次检查（`updater.OnChange`）后，kura 自己调一次 `mygo.Updater.Check(ctx)`，有新版本就把界面上的「有新版本」状态置真 → 小蓝点。为了不白跑请求，用 `updater.LastCheck()` 去重（时间没变就跳过；用户点开关这类也会触发 OnChange，但 `LastCheck` 没变）。查询失败时**不改**蓝点状态（不因网络抖动把它抹掉）。
- 这段「监听 + 自己查」的代码放 `internal/selfupdate`（那里才允许 import `plugins/updater`），**只在 `main.go` 接线**；`internal/ui` 只拿一个 `func(bool)` 回调和两个读写钩子，测试里注入假实现。
- 小蓝点**只在**左栏那个「检查更新」按钮上，**不能改变按钮的位置与尺寸**（不挤压图标与相邻按钮），**不能吃掉点击**（用 MyGo 的 `PassThrough()`）。
- 点「检查更新」按钮时**立刻清掉**蓝点（用户已经在看更新窗口了）；后台查到「没有新版本」时也清掉。
- 「自动检查更新」开关**不做**成 `mygo.App` 菜单项，也不动 MyGo 自己的更新窗口文案。

## 具体要求

### 1. `internal/selfupdate`：新增三个薄转发

- `AutomaticChecks() bool` → `updater.AutomaticChecks()`；`SetAutomaticChecks(on bool)` → `updater.SetAutomaticChecks(on)`。
- `WatchUpdateFound(found func(available bool)) (off func())`：注册 `updater.OnChange`；每次回调时（在**后台 goroutine** 里，不要阻塞主线程）用 `LastCheck()` 去重后调一次 `mygo.Updater.Check(ctx)`（带超时，如 30 秒），把「是否发现新版本」交给 `found`（由调用方负责回主线程）。返回取消函数（供测试/将来用；实现上就是 `OnChange` 返回的 off）。注释写清：为什么需要它（插件没有这个回调）、为什么要自己去重、失败时为什么不动状态。
- 这些函数与现有 `CheckForUpdates` 一样：只转发、不含更新逻辑，且都依赖插件已挂载。

### 2. `internal/ui`：状态与钩子

- 新增字段：`autoCheck bool`（「自动检查更新」当前值，默认 `true`）、`updateFound bool`（后台查到有新版本）、`autoCheckGet func() bool` / `autoCheckSet func(bool)`。
- `NewApp` 里 `autoCheck` 默认 `true`（默认勾上）；钩子保持 nil（测试与未接线时不得 panic）。
- 新增 `SetAutoChecks(get func() bool, set func(bool))`：注入生产实现（`main.go` 在窗口就绪后调 `app.SetAutoChecks(selfupdate.AutomaticChecks, selfupdate.SetAutomaticChecks)`），注入时用 `get()` 初始化 `a.autoCheck`。与 `SetCheckUpdates` 同样只在生产路径接线。
- 新增 `SetUpdateFound(available bool)`：设置 `a.updateFound`，**可从任意 goroutine 调用**（内部经 `a.publish` 回主线程，照 `CheckAppUpdateAsync` 的范式）。钩子为 nil 时 `autoCheckSet` 那侧不要 panic（照 `SetCheckUpdates` 的兜底：钩子为 nil 时只在状态行报告「更新功能未就绪」）。
- `CheckAppUpdateAsync`：点击时清掉 `updateFound`（并请求重绘），其余不变。
- 新增 `SetAutoCheckAsync(on bool)`：立刻改 `a.autoCheck`、调 `autoCheckSet(on)`（后台，经 `a.spawn`）、失败只在状态行报告、连续切换只有最新一次生效（照 `SetViewAsync` 的序号范式）。

### 3. `internal/ui/settings.go`：设置弹窗里的开关

- 在设置弹窗里加「自动检查更新」一项（开关在右，标签在左，样式与左栏底部的外观开关同一套 `kuraSwitch`）。放在「界面语言」附近、翻译那一组之外（这是「更新」这一类，不是翻译），组与组之间给一点间隔或一条分隔线，别把现有五项挤乱。
- 绑定写法照 `viewCard`/`viewThemeSwitch`：`on := a.autoCheck; if kuraSwitch(c, &on, a.pal.toggle).Label(...).Changed() { a.SetAutoCheckAsync(on) }`（`Changed()` 返回 true 的那一次构建里局部变量已是新值）。**不要**写成构建中途直接比较局部变量。
- 开关有独立的无障碍名（`Label`），供测试与无障碍查找；文案进 `locales/`。

### 4. `internal/ui/view.go` / `theme.go`：小蓝点

- `theme.go`：给 `tone` 与 `palette` 加一个「有新版本」的圆点颜色（例如 `notify`），浅色与深色各给一个值。要求：**明显看得出是蓝色**、但不要霓虹/高饱和的蓝紫，且与强调色 `Accent`（浅 `#5b668f` / 深 `#818bbf`）明显不同。**十六进制只写在 `theme.go` 里**。
- 左栏底部那个「检查更新」按钮：`a.updateFound` 为真时在按钮**右上角**画一个小圆点。做法建议：在按钮的子元素里放一个 `myui.Box(c).Size(d,d).Radius(d/2).Background(a.pal.notify).Absolute().Top(...).Right(...).PassThrough()`（`Absolute` + `Top`/`Right` 是相对父元素的位置，`PassThrough` 保证不吃点击）。圆点可以再描一圈与背景同色的细边，避免与图标糊在一起。`railButton` 的签名可以加一个参数（只有这个按钮用）或另建一个变体，两者都行——由你定，但不得影响「设置」按钮。
- 蓝点**绝不**改变按钮的布局尺寸：加上蓝点前后，`tt.Find("检查更新")` 的矩形必须逐像素一致。
- 可选加分项：`a.updateFound` 为真时把该按钮的悬停提示换成一条「有新版本可用」的文案（`railButton` 的 `tip` 参数）。要做就一并加文案与测试；不方便测就说明并把理由写进报告。

### 5. 文案（i18n）

- 新文案进 `locales/en.json`（source）与 `locales/zh-Hans.json`，key 用**扁平 camelCase**（例如 `uiSettingsAutoCheckUpdate`、`uiRailUpdateAvailableTip`），中文是用户实际看到的文案。
- 改完跑 `go tool mygo generate` 重新生成 `locales/catalog_gen.go`（生成物入库）。

- 不要改任何既有文案的措辞。

### 6. `main.go` 接线

在窗口就绪后（`app.SetCheckUpdates(...)` 旁边）加：

```go
app.SetAutoChecks(selfupdate.AutomaticChecks, selfupdate.SetAutomaticChecks)
selfupdate.WatchUpdateFound(app.SetUpdateFound)
```

（`SetUpdateFound` 必须能吃后台 goroutine 的调用。）
