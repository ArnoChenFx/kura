# 任务：把 kura 的界面文案搬进 i18n 目录，实现中英双语（第二批：internal/ui）

仓库根就是当前目录（这是给你新建的 worktree）。先读 `_AGENTS.md`（= 仓库的
`AGENTS.md`，工程约定）与 `REQUIREMENTS.md`，再读 `internal/i18n/i18n.go` 的
包注释——那是这套机制的权威说明。

## 背景

kura 现在界面只有中文。用户要求：**下一版支持中英双语，第一次打开时跟随系统
语言——系统是中文就用中文，否则一律英文**。

基础已经由我（主管）写好并提交（就在你的基线里）：

- `internal/i18n`：进程级当前语言 + 各包自己的文案目录。
  - 取文案：`i18n.T(key)`、`i18n.Tf(key, args...)`。
  - 当前语言：`i18n.Set(lang)`、`i18n.Current()`（`i18n.ZH` / `i18n.EN`）。
  - 错误：`i18n.NewError(key, args...)`、`i18n.Errorf(key, args...)`、
    `i18n.Wrapf(err, key, args...)`（身份稳定、文字随语言变，`errors.Is` 可用）。
  - 语言解析：`i18n.Resolve(pref, locale)`、`i18n.FromLocale` —— `zh*` 是中文，
    其余（含空、C、POSIX）一律英文。
- `internal/store` 已有 `NormalizeLang` / `LangPref` / `Library.SetLang` /
  `Library.Lang`（config.json 的 `lang` 字段：system | zh | en）。
- `internal/i18n` 里有守卫测试 `TestNoHardcodedCJK`：**非测试的 Go 文件里只要
  还有中文界面字面量它就失败，并逐条列出行号**。它是你这份活的验收尺子。

### 硬性要求

- **中文取值必须与现状逐字一致**（既有测试断言了大量中文按钮/标题/状态行，
  它们不能改）。英文取值要自然、简短；`%s`/`%d` 占位符两种语言顺序一致。
  整句进目录，**不拼接**。
- **key 命名**：`ui.<领域>.<名字>`，全小写 ASCII、点分隔，例如
  `ui.filter.all`、`ui.status.installFailed`、`ui.install.title`、
  `ui.settings.targetLang`。全包共用一个 `catalog.go`：
  ```go
  package ui

  import "github.com/ArnoChenFx/kura/internal/i18n"

  // 中文文案：与改造前的界面文字逐字一致。
  var catalogZH = map[string]string{
      "ui.filter.all": "全部",
      // …
  }

  // 英文文案：key 与中文一一对应（含同样的占位符）。
  var catalogEN = map[string]string{
      "ui.filter.all": "All",
      // …
  }

  func init() { i18n.RegisterZH(catalogZH); i18n.RegisterEN(catalogEN) }
  ```
  两个 map 的 key 集合必须完全一致。
- **不要翻译的东西**（留在代码里 + 加注释说明理由）：
  - 用户数据：技能名、路径、`owner/repo`、URL。
  - `targetLangs` 里语言的自称（`简体中文`、`日本語`、`Français`…）：两种界面
    语言下都显示自称，这才对。
  - `markdown.go` 里作为**语法**用的字符：列表符号 `•`、`◦`、`▪`，以及
    `".,;:!?)]}\"'，。；：！？）"` 这种标点集合——它们是解析用的字符集，
    不是文案。**但** `mdTruncatedNotice`（"（内容过长，已截断）"）与
    `"…（另有 N 行未显示）"` 是真正的界面文案，要进目录。
  - 日志、注释、测试里的中文。
- **状态行与错误**：`a.status = "..."` 这类改 `i18n.T(...)` / `i18n.Tf(...)`。
  store 返回的错误文案由 store 自己翻译（它的目录归另一个 agent），UI **不要**
  去 match 错误文本、也不要再包一次；直接显示 `err.Error()`。
- **界面语言变量**：App 需要一个字段记住当前偏好（`store.LangSystem`/`LangZH`/
  `LangEN`），并接 `Library.SetLang`。语言解析（system → 具体语言）**在 main.go
  与 CLI 里做**（另一个 agent 负责 main.go），UI 只需要：
  1. `App` 记住偏好；
  2. 提供 `SetLangAsync(pref string)`（照 `SetThemeAsync` / `SetViewAsync` 的
     模式：先改内存 + `i18n.Set(解析后的语言)` + `Invalidate`，写盘在后台，
     失败只在状态行报告、不回滚）；
  3. 在设置弹窗里加一个「界面语言 / Language」下拉（跟随系统 / 简体中文 /
     English），并显示当前值；
  4. 语言变化后重绘整个界面（文案是每帧现取的，天然会变）。
  解析具体语言用 `i18n.Resolve(i18n.Lang(pref), locale)`；窗口里系统 locale 用
  `i18n.SystemLocale()`。
